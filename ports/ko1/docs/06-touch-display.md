# 06 · 触摸与刷新

## 结论先说

**输入链路是干净的，慢在显示刷新。** "不太跟手"不是触摸驱动的问题，抓数据就能看出来。

## 触摸链路的数据

抓 120 条触摸事件，按 `SYN_REPORT` 分帧还原轨迹：

| 观察 | 实测 |
|---|---|
| 帧间隔 | 中位数 **16 ms**（约 62 Hz） |
| 连续拖动中的丢帧 | **没有**，相邻帧坐标连续 |
| 快速划动 | 208 ms 内从 (843, 27) 到 (771, 691)，每帧 `dy` 由 40 增大到 97，平滑加速 |
| 坐标范围 | Y 轴 27–1416 全屏覆盖，读数准确 |

帧率稳定、无跳点、无卡顿——从手指到内核到 Android 的路径上没有可优化的地方。

## 慢在哪

EPDC 刷屏。电子墨水屏每次更新要跑波形，一次刷新的时间远大于 16 ms，
所以手指移动 60 次，屏幕只来得及画几次。这是墨水屏的物理属性，不是"驱动没调好"。

## 为什么没顺手改掉

用户态没有调节入口。production build 下：

```
/sys/class/graphics/fb0/*                      SELinux 拒
/sys/module/mxc_epdc_fb/parameters/*           SELinux 拒
```

也就是说 A2 / DU / GC16 这类更新模式**没法从用户态选**。要真正改善，得动显示栈
（在 EPDC 驱动或 SurfaceFlinger 侧按场景挑更新模式），那是另一个量级的工作，本阶段没做。

## 隐私屏保与休眠

顺带记录一条没做的东西：休眠时的屏保（`/mnt/us/system/...` 那套）走的是原厂系统的路径，
Android 侧没有接。不影响使用，但"锁屏显示什么"目前是空白。
